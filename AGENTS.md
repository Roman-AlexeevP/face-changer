# AGENTS.md

Инструкции для агентов и людей, работающих с этим репозиторием.

## О проекте

Telegram-бот: пользователь присылает фото, бот подставляет лицо в видео-шаблон
через Higgsfield API (Genjutsu) и возвращает видео. Рынок РФ, MVP на заглушках
оплаты и движка.

Контекст: [`openspec/project.md`](openspec/project.md).
Архитектура: [`docs/architecture.md`](docs/architecture.md).
План: [`docs/implementation-plan.md`](docs/implementation-plan.md).

## Сначала спецификация, потом код

Проект ведётся по OpenSpec. Перед реализацией любой фичи:

1. Изменение создаётся в `openspec/changes/<change-id>/` — `proposal.md`,
   `design.md`, `tasks.md`, `specs/<capability>/spec.md` (дельта с
   `## ADDED Requirements`).
2. Проверка обязательна: `openspec validate --all`.
3. Код пишется по задачам из `tasks.md`, а не по памяти.

Не начинай писать код в обход спецификации. Если требования противоречат
коду — сначала правь спецификацию.

## Стиль кода: функциональный подход

Базовый принцип — **функциональное ядро, императивная оболочка**. Бизнес-логика
это чистые функции над неизменяемыми данными; всё, что общается с миром,
живёт на краю и тонкое.

### Чистое ядро (`app/domain/`)

- Только чистые функции: один и тот же вход — один и тот же выход, без
  обращений к БД, сети, времени, файлам и случайности.
- Всё, что влияет на результат, передаётся параметром: `now`, `new_id`,
  `rng`. Функция не читает часы сама.
- Данные — `@dataclass(frozen=True)`, изменение только через
  `dataclasses.replace`.
- Аргументы не мутируются никогда.
- Импорт `aiogram`, `sqlalchemy`, `httpx`, `os`, `time` внутри `domain/`
  запрещён. Это правило проверяется тестом.

```python
# app/domain/order_service.py
def pay(order: Order, now: datetime) -> Result[Order, OrderError]:
    if order.status is not OrderStatus.CREATED:
        return Err(AlreadyPaid(order.id))
    return Ok(replace(order, status=OrderStatus.PAID, paid_at=now))
```

### Императивная оболочка (`bot/`, `worker/`, `payments/`, `engines/`, `db/`)

- Здесь разрешены побочные эффекты, I/O и классы-клиенты.
- Оболочка не содержит бизнес-правил: она читает данные, зовёт чистую функцию,
  сохраняет результат, отправляет сообщение.
- Порядок обработки: `parse → validate (чистое) → decide (чистое) →
  persist (эффект) → notify (эффект)`.

### Ошибки как значения

- В домене ошибка — это значение: `Result[T, E]`, без `raise`.
- Исключения допустимы только для нарушения инвариантов (ошибка
  программиста) и на границе с внешним миром (битый JSON, HTTP-ошибка),
  где они сразу превращаются в `Err`.
- Ошибка домена — типизированный `dataclass`, а не строка.

### Нет скрытых зависимостей

- Никаких глобальных изменяемых состояний и синглтонов.
- Зависимость приходит аргументом или через `Protocol`, реализация
  подставляется в точке сборки (`main_bot.py`, `main_worker.py`).
- `Protocol` вместо базовых классов; наследование не используется.

## Декомпозиция

Главное правило: **одна функция — одно действие, и его видно из названия.**

| Что | Предел |
|---|---|
| Длина функции | 25 строк (жёстко — 40) |
| Позиционных параметров | 3 (больше — собирай `dataclass`) |
| Уровень вложенности | 2 |
| Длина модуля | 300 строк |
| Модулей в пакете | без «utils», «helpers», «common» |

- Название — глагол и объект: `build_invoice`, `parse_engine_error`.
  Слова `process`, `handle`, `manage`, `do` — признак, что функция делает
  несколько вещей.
- Если в названии нужно «and» — это две функции.
- Если нужен комментарий «что делает» — декомпозируй, а не комментируй.
- Функция либо считает, либо делает. Не оба.
- Композиция вместо ветвлений: маленькие функции, собранные в пайплайн.

## Запрещено

- Мутировать аргументы и возвращать их же.
- Классы с изменяемым состоянием (кроме тонких клиентов внешних API).
- `global`, изменяемые значения по умолчанию, скрытые модульные кеши.
- Бизнес-правила в хендлерах бота и в SQL.
- Прямая запись `order.status` — только через чистую функцию перехода.
- Логирование PII: фото, имена, `tg_id` в открытом виде, URL с подписью.
- `time.sleep` в async-коде.

## Тесты

- Домен — юнит-тесты без БД и сети. Если для теста нужен мок времени —
  значит время не передали параметром, чини код, а не тест.
- Порты (`VideoEngine`, `PaymentProvider`, `Storage`) — фейки в тестах.
- Один сквозной тест на `ENGINE=mock`, `PAYMENT_PROVIDER=stub`.
- Тест архитектуры: `domain/` не импортирует инфраструктуру.

## Команды

Всё в контейнерах, хостовое окружение не требуется:

```powershell
.\tasks.ps1 test      # pytest + HTML-отчёт в reports/
.\tasks.ps1 lint      # ruff check + ruff format --check
.\tasks.ps1 migrate   # alembic upgrade head (одноразовая джоба)
.\tasks.ps1 up        # postgres + bot + worker
```

Без обёртки: `docker compose --profile test run --rm tests`,
`docker compose --profile tools run --rm migrate`.

Спецификации: `openspec validate --all`.
